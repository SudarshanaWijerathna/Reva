# Rental Model Dataset Schema

This schema documents the outputs generated by `scripts/preprocess_rental_data.py`.

## Outputs

- `data/processed/rental_cleaned.csv`: canonical audit dataset with raw-derived values, anomaly flags, and exclusion reasons.
- `data/features/rental_features_v1.csv`: model-ready training dataset. Rows with impossible prices, impossible extracted values, non-rental listing types, or duplicate records are excluded.
- `reports/rental_data_quality_report.json`: row counts, exclusions, target distributions, feature columns, and legacy combined-file audit.

## Target

- `monthly_rent_lkr`: monthly rental price in Sri Lankan rupees.
- `log_monthly_rent_lkr`: `log1p(monthly_rent_lkr)`, included as a helper target for training experiments.

## Core Fields

- `source`, `source_file`, `listing_id`, `listing_url`: source lineage fields.
- `property_type`: normalized rental segment, such as `Apartment`, `House`, `Office space`, `Warehouse`, `Room`, `Annex`, or `Villa`.
- `location`, `district`: normalized listing location fields where available.
- `bedrooms`, `bathrooms`, `floor_area_sqft`, `land_perches`, `floor_number`, `car_parking_spaces`: numeric property attributes. Missing numeric feature values are zero-filled in the feature CSV.
- `furnishing_status`: normalized to `furnished`, `semi-furnished`, `unfurnished`, or `unknown`.
- `short_term` and `is_short_term`: short-term rental indicator derived from explicit fields and listing text.
- `deposit_months`, `advance_months`, `lease_term_months`: term fields converted to months.

## Categorical Training Columns

Defined in `ml/rental_service/feature_schema.py`:

- `property_type`
- `district`
- `location`
- `furnishing_status`
- `source`

These are intentionally kept as string columns for CatBoost-compatible training.

## Amenity Columns

Amenity fields use the `amenity_` prefix and are binary indicators derived from structured feature lists and listing text. Examples include:

- `amenity_swimming_pool`
- `amenity_24_hour_security`
- `amenity_ac_rooms`
- `amenity_gym`
- `amenity_on_site_parking`
- `amenity_private_entrance`

The complete list is maintained in `ml/rental_service/feature_schema.py`.

## Quality Flags

The cleaned audit dataset includes binary flags plus a pipe-delimited `anomaly_flags` field:

- `flag_missing_price`
- `flag_impossible_price`
- `flag_extreme_price`
- `flag_impossible_area`
- `flag_extreme_area`
- `flag_impossible_land`
- `flag_extreme_land`
- `flag_impossible_rooms`
- `flag_non_rental_listing`
- `flag_duplicate_exact`
- `flag_duplicate_identifier`
- `flag_duplicate_near`

Rows with exclusion-worthy issues are retained in `rental_cleaned.csv` with `is_training_excluded = 1` and a pipe-delimited `exclusion_reason`, but are omitted from `rental_features_v1.csv`.

## Outlier Policy

The pipeline uses property-type-aware bounds. Impossible extraction errors are excluded from training, while plausible but high-end listings are flagged and retained. This prevents room rentals, luxury apartments, and commercial properties from being judged by the same rent and size thresholds.
